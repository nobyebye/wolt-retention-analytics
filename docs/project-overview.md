# Wolt 业务场景：用户留存与复购分析

## 公司与业务背景

Wolt 是创立于芬兰赫尔辛基的配送平台，业务涵盖餐饮与零售。项目以其公开的客户购买数据题目为业务背景，分析不同首购业务线用户的留存、复购和跨业务线购买行为。
公司背景参考 [Wolt 官方介绍](https://explore.wolt.com/en/fin/about)，数据来源与适用范围见 [指标口径文档](metric-contract.md)。

## 解决了什么问题

### 首购与购买数据难以直接关联

两份源文件的订单 ID 没有重合，部分购买用户也没有首购记录。直接拼表会遗漏用户或错误归属获客月份。
项目以首购表建立用户锚点，保留原始数据，核对订单与用户关系，隔离 10,145 条无法归属的购买记录，最终构建包含 71,257 名用户、288,569 条购买事件的分析数据集。

### 用户留存缺少一致的分析口径

只分析有后续购买的用户会高估留存；将未完整观察的月份记为零，则会低估留存。
项目按首购月份和首购业务线建立同期群，保留全部首购用户作为分母，对不完整月份使用空值，并分别计算平台留存和同业务线留存，形成可比较的指标。

### 复购与跨业务线购买缺少统一视图

项目对具有完整 30 天观察期的用户计算复购率与跨线购买率，并在交互看板中展示两条业务线的差异。
当前数据集中，餐饮首购组的 30 天复购率为 13.25%，零售首购组为 18.43%；两组样本量分别为 51,957 与 331，差异仅作描述性分析，具体解释见 [分析报告](analysis-report.md)。

### 分析流程难以稳定重复执行

使用 Python 进行字段校验和参数化批量导入，使用 MySQL 建立用户维度、购买事实与指标汇总表。
通过事务全量刷新、并发互斥、运行日志和 7 项质量检查保障数据一致性；13 项单元及 MySQL 集成测试覆盖重复执行、观察期边界和中途失败回滚。

## 项目交付

- 从数据下载、校验、对账到 MySQL 汇总的完整处理流程。
- 月度留存、30 天复购和跨业务线购买 SQL 模型。
- 可筛选的留存热力图、复购对比看板及 CSV 导出。
- 指标文档、数据质量记录、分析报告和查询性能实验。
- Docker Compose 部署配置与 GitHub Actions 自动测试。

技术栈：MySQL 8、Python、SQL、Streamlit、Docker Compose、GitHub Actions。
